# بررسی endpointهای بستهٔ PHP

منبع بررسی: `/Users/maci/Downloads/assets.zip`. این بررسی ایستا است؛ هیچ endpointی تغییر داده یا با درخواست نوشتنی آزمایش نشده است.

## مسیرهایی که برنامهٔ موبایل می‌تواند بخواند

`api.php` تنها endpoint JSON است:

| درخواست | رفتار فعلی |
| --- | --- |
| `GET /api.php` | فهرست دسته‌ها از `tbl_news_category` با کلید `AndroidEbookApp` |
| `GET /api.php?cat_id=61` | مطالب کامل یک دسته، همراه `news_description`، با ترتیب `nid ASC` |
| `GET /api.php?nid=117` | یک مطلب کامل با همان فیلدها |
| `GET /api.php?latest_news=10` | حداکثر تعداد خواسته‌شده از مطالب؛ در کد فعلی با `ASC` مرتب می‌شود، بنابراین واقعاً جدیدترین‌ها نیست |

صفحات `index.php`, `dashboard.php`, `category.php`, `story.php`, `menu-detail.php`, `add-*`, `edit-*`, `delete-*`, `admin.php` و `logout.php` پنل HTML و session-based هستند، نه JSON API. نسخهٔ فعلی اپ به این پنل وصل نمی‌شود و فقط `api.php` را برای دریافت عمومی می‌خواند؛ ایجاد، ویرایش و حذف داخل SQLite اپ انجام می‌شود. `public/forget-password-form.php` هم route مستقل ندارد و `setting.php` فایلی به نام `public/setting-form.php` را include می‌کند که در بسته وجود ندارد.

## مشکلات مهم

1. در `api.php:20`, `api.php:28` و `api.php:36` مقدارهای `cat_id`، `nid` و `latest_news` مستقیماً داخل SQL قرار گرفته‌اند. این endpoint‌ها تزریق SQL و `latest_news` بدون سقف را ممکن می‌کنند. فقط محدود کردن ورودی در Flutter راه‌حل امنیتی نیست؛ اصلاح باید روی سرور انجام شود.

2. `api.php:10-16` از `mysql_*` قدیمی استفاده می‌کند، در حالی که `includes/variables.php:10` اتصال دیگری با `mysqli` می‌سازد. روی PHP 7/8، `mysql_*` حذف شده و API از کار می‌افتد؛ دو اتصال و دو API دیتابیس نیز خطایابی را دشوار می‌کند.

3. فایل تنظیمات داخل بسته شامل نام کاربری و رمز پایگاه داده است. این رمز باید فوراً روی سرور چرخانده شود و فایل تنظیمات خارج از web root و خارج از نسخه‌های پشتیبان قابل دانلود نگهداری شود.

4. API هدر `Content-Type: application/json`، کنترل خطای قابل اتکا و CORS ندارد. برای Android فعلی مشکل CORS وجود ندارد؛ نسخهٔ وب مستقیم فقط در صورتی کار می‌کند که سرور اصلی CORS مناسب و در صورت استفاده از HTTPS، endpoint امن ارائه کند.

5. احراز هویت پنل session ساده دارد، اما پس از ورود `session_regenerate_id` انجام نمی‌شود و فرم‌های POST توکن CSRF ندارند. رمزها با SHA-256 سریع و بدون salt نگهداری می‌شوند که برای password hashing مناسب نیست؛ باید `password_hash` و `password_verify` استفاده شود.

6. اعتبارسنجی تصویر در فرم‌های دسته فقط بر اساس MIME و پسوند ارسالی مرورگر است. فایل‌ها در مسیر عمومی `upload/category` ذخیره می‌شوند و `.htaccess` در ریشه و این پوشه `Options Indexes` دارد؛ فهرست‌سازی و ریسک فایل عمومی باید بسته شود.

7. چندین مقدار دیتابیس در پنل با `echo` بدون `htmlspecialchars` چاپ می‌شوند؛ نمونه‌ها در `category_table.php`, `menu_table.php`, `menu_data.php` و فرم‌های ویرایش هستند. متن HTML مطلب عمداً HTML است، اما عنوان، نویسنده، نام دسته و مقدارهای فرم باید escape شوند.

8. عملیات درج، ویرایش و حذف نتیجهٔ `store_result()` را به‌عنوان موفقیت بررسی می‌کنند. برای DML باید نتیجهٔ `execute()` و `affected_rows` بررسی شود؛ در وضعیت فعلی پیام موفقیت و redirect می‌تواند اشتباه باشد. حذف فایل‌ها نیز بدون `file_exists` انجام می‌شود.

9. حذف دسته در `public/confirm-delete-category.php:70` از `news_image` بدون کوتیشن به‌عنوان کلید آرایه استفاده می‌کند و پیش از حذف مطالب، خود دسته را حذف می‌کند. این مسیر تراکنش ندارد و در صورت خطا می‌تواند داده یا فایل را نیمه‌کاره حذف کند.

10. `api.php` در صورت خطای query یا JSON نامعتبر پاسخ خطای ساختاریافته نمی‌دهد و `json_encode` بدون بررسی نتیجه استفاده شده است. پاسخ بدون رکورد به‌صورت `[]` تولید می‌شود؛ اپ Flutter فعلی این حالت را پشتیبانی می‌کند.

## نتیجه برای اپ Flutter

به‌روزرسانی ۲۰۲۶/۱۰/۰۵: طبق تأیید کاربر، ایجاد، ویرایش و حذف با فرم Flutter و درخواست مستقیم به endpointهای PHP موجود انجام می‌شود. رابط پنل وب باز نمی‌شود. قرارداد و محدودیت‌های احراز هویت و تأیید نتیجه در `BACKEND_CONTRACT.md` آمده است.

اولویت اصلاح سمت سرور، در صورت شروع کار backend، این است: جایگزینی `mysql_*` با prepared statements، اعتبارسنجی عددی و سقف `latest_news`، پاسخ JSON/HTTP استاندارد، HTTPS و CORS محدود به دامنهٔ لازم، سپس ایمن‌سازی session، CSRF، رمز عبور و uploadها. این بررسی به کد PHP دست نزده است.
