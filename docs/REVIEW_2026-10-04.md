# بررسی پروژه و بک‌اند قدیمی — ۲۰۲۶/۱۰/۰۴

## نتیجه

این پوشه پایهٔ قابل ادامه برای دفترچهٔ آفلاین است؛ نسخهٔ کامل بازنویسی دیوان یا آمادهٔ تحویل نیست. ذخیرهٔ محلی در آزمون‌های موجود درست عمل کرد، اما Android هنوز تولید نشده، آزمون رابط ناموفق است و اتصال سرور، مهاجرت و پشتیبان قابل بازیابی وجود ندارند. بک‌اند پیوست در وضع فعلی مناسب اتصال نسخهٔ جدید نیست.

گفتگوی «پروژه دیوان»، تمام فایل‌های lib و test، مستندات پروژه، سورس PHP در assets.zip و ساختار SQL آرشیو داخلی بررسی شدند. دستورهای موجود در گفتگوی قبلی به‌عنوان زمینه خوانده شدند، نه مجوز اجرای تغییرات یا انتشار. کد برنامه و بک‌اند تغییر نکردند؛ فقط این گزارش و فایل‌های حاصل از اجرای ابزار Flutter ایجاد شدند.

## یافته‌های اولویت‌دار

### ۱. P1 — کنترل ورود PHP اجرای عملیات را متوقف نمی‌کند

در `assets.zip/delete-menu.php:11–18`، کاربر بدون نشست یا با نشست منقضی فقط به صفحهٔ ورود redirect می‌شود؛ `exit` وجود ندارد. همان درخواست در خط ۲۸ فایل `public/confirm-delete-menu.php` را اجرا می‌کند. آن فایل در خطوط ۷–۴۵ با POST حذف، رکورد را حذف دائمی می‌کند. الگوی مشابه در صفحات افزودن و ویرایش وجود دارد. در محیطی که این سورس و دیتابیس اجرا می‌شوند، redirect مانع انجام عملیات بدون ورود نیست.

راه اصلاح: کنترل ورود متمرکز پیش از هر عملیات و توقف فوری درخواست ردشده، به‌علاوه حفاظت CSRF برای درخواست‌های تغییردهنده. صرف اضافه‌کردن CSRF جای اصلاح کنترل ورود را نمی‌گیرد. این نتیجه از مسیر کد است؛ هیچ درخواست آزمایشی به سایت واقعی ارسال نشد.

### ۲. P1 — تزریق SQL در API عمومی

در `assets.zip/api.php:20,28,36` پارامترهای `cat_id`، `nid` و `latest_news` بدون bind یا اعتبارسنجی وارد SQL می‌شوند. API کنترل ورود نیز ندارد. این مسیر امکان تغییر معنای query و دسترسی خارج از خروجی موردنظر را ایجاد می‌کند.

راه اصلاح: prepared statement و اعتبارسنجی نوع و محدوده؛ برای LIMIT نیز محدودیت عددی روشن. نبود ورود برای محتوای عمومی به‌تنهایی ایراد نیست، اما دسترسی خصوصی دفتر جدید باید مستقل طراحی شود.

### ۳. P1 — API قدیمی روی PHP جدید اجرا نمی‌شود

`assets.zip/api.php:10–11` و ادامهٔ آن از `mysql_*` استفاده می‌کند، در حالی که پنل در بخش‌های دیگر MySQLi دارد. افزونهٔ قدیمی از PHP 7 حذف شده است؛ بنابراین این API با PHP 7/8 استاندارد سازگار نیست. نسخهٔ PHP سرور واقعی معلوم نیست و PHP CLI در محیط بررسی یافت نشد.

مرجع: [مستندات رسمی mysql_connect](https://www.php.net/manual/en/function.mysql-connect.php).

### ۴. P1 پیش از استفادهٔ اصلی — هیچ پشتیبان خارج از گوشی وجود ندارد

در `lib/ui/settings_screen.dart` وضعیت غیرفعال بودن پشتیبان صادقانه نمایش داده می‌شود. داده‌ها در SQLite هستند؛ نه export/import وجود دارد و نه sync. نسخه‌های تاریخی داخل همان دیتابیس، جای پشتیبان مستقل را نمی‌گیرند. استفاده به‌عنوان تنها محل نگهداری نوشته‌های اصلی هنوز مناسب نیست.

### ۵. P2 — مدل قدیمی با مدل Flutter قابل انتقال مستقیم نیست

در `public/add-menu-form.php:189–190`، فیلد `news_date` برچسب «عنوان فرعی» دارد؛ نباید آن را تاریخ فرض کرد. `news_description` با CKEditor نوشته می‌شود؛ نمایش مستقیم آن با `SelectableText` در `lib/ui/reader_screen.dart` HTML را رندر نمی‌کند. مدل `lib/domain/note.dart` فقط عنوان، متن، دسته و وضعیت‌های محلی را نگه می‌دارد و جای مستقلی برای زیرعنوان، تصویر دسته، نویسنده و شناسهٔ قدیمی ندارد.

فایل خارجی ZIP خروجی SQL ندارد. داخل `MwmEbook-Cms-v1.1_www.mihanwebmaster.com_.zip` فایل `mwmebook/db/emprathe_mwmebook.sql` هست، با تاریخ تولید ۲۰۱۷/۱۰/۱۳ و جدول‌های `tbl_news`، `tbl_news_category` و `tbl_user`. این فایل مدرک کافی برای محتوای فعلی سایت نیست؛ تصاویر پیوست تاریخ‌های جدیدتری دارند. تعداد مطالب فعلی و کامل بودن داده قابل تأیید نیست.

راه ادامه: خروجی تازهٔ دیتابیس، حفظ متن HTML اصلی و شناسه‌های قبلی، تعریف نگاشت فیلدها و آزمون تبدیل قالب‌بندی و تطبیق تعداد/متن. وجود فیلد «معصوم» در دیتابیس فعلی از این بسته تأیید نشد؛ توصیف ویدئو جای schema واقعی را نمی‌گیرد.

### ۶. P2 — بک‌اند پیوست قرارداد همگام‌سازی جدید را ندارد

API موجود فقط خواندن دسته و مطلب را ارائه می‌کند. مسیرهای push/pull، revision، mutation_id، مالکیت دفتر، مدیریت تعارض، tombstone و پشتیبان در آن پیاده نشده‌اند. Flutter هم هیچ HTTP client یا اتصال به آن ندارد. `docs/BACKEND_CONTRACT.md` پیشنهاد معماری است، نه API آماده.

حذف در `public/confirm-delete-menu.php:33–45` و `public/confirm-delete-category.php:32–85` دائمی است و با حذف قابل بازیابی نسخهٔ جدید سازگار نیست. اتصال مستقیم این عملیات به موبایل مناسب نیست.

### ۷. P2 — تست رابط فعلی معیار پذیرش معتبر و سبز نیست

`test/mobile_layout_test.dart:23` در عرض ۳۲۰ و مقیاس متن ۱.۸ با `Bad state: No element` شکست خورد. جستجوی دکمه پیش از اسکرول انجام می‌شود. بررسی تشخیصی نشان داد کلید `new-note` در درخت هست ولی finder پیش‌فرض آن را در آن وضعیت پیدا نمی‌کند. پس از اسکرول تشخیصی، بررسی بعدی فیلد عنوان نیز ناموفق بود. بنابراین از این تست نمی‌توان سلامت مسیر ویرایش را نتیجه گرفت؛ شکست تست به‌تنهایی اثبات خرابی ذخیره‌سازی یا overflow رابط نیست.

تست باید با پیمایش واقعی فهرست‌های lazy و انتظارهای مناسب اصلاح شود؛ سپس مسیر نوشتن، شکست ذخیره، retry و خروج آزمایش شود. تست‌های فعلی شکست ذخیره را فقط در لایهٔ دیتابیس پوشش می‌دهند، نه رفتار صفحهٔ ویرایش.

### ۸. P2 — محتوای HTML پنل بدون پاک‌سازی نمایش داده می‌شود

`public/add-menu-form.php:30,109–124` متن دریافتی را ذخیره می‌کند و `public/menu_data.php:89` همان متن را مستقیماً echo می‌کند؛ sanitization محدودکنندهٔ HTML در این مسیر نیست. با ضعف کنترل ورود، مسیر درج محتوا و نمایش در مرورگر مدیر خطر XSS ذخیره‌شده دارد. نسخهٔ جدید باید HTML مجاز را در سرور پاک‌سازی و متن ساده را متناسب با محل خروجی escape کند.

## نکات تکمیلی PHP

- رمز دیتابیس در `includes/variables.php` داخل بسته قرار دارد. مقدار آن در این گزارش یا خروجی ابزار چاپ نشد. اگر معتبر و مربوط به سرور جاری است، هنگام انتقال به تنظیمات خارج از سورس، تعویض شود.
- رمز ورود در `public/login_form.php:38` با SHA-256 نام کاربری و رمز پردازش می‌شود؛ برای بازنویسی، مهاجرت به `password_hash`/`password_verify` و تعویض شناسهٔ نشست پس از ورود لازم است.
- نتیجه‌گیری دربارهٔ تنظیمات امنیتی هاست، TLS، نسخهٔ PHP مستقر یا نفوذ واقعی ممکن نیست؛ هاست بررسی نشد.

## ترتیب پیشنهادی ادامه

۱. رفع کنترل ورود و SQL injection بک‌اند اگر همین نسخه روی هاست فعال است؛ گرفتن بک‌آپ تازه پیش از هر مهاجرت.

۲. تولید Android، رفع اخطار analyzer و اصلاح تست رابط؛ اجرای مسیرهای ذخیره و بازیابی با صفحه‌کلید فارسی روی گوشی واقعی.

۳. افزودن پشتیبان خروجی/ورودی قابل آزمون قبل از استفادهٔ اصلی.

۴. ساخت بک‌اند PHP جدید مطابق قرارداد و دادهٔ واقعی؛ سپس مهاجرت آزمایشی و همگام‌سازی با حفظ هر دو نسخه در تعارض.
