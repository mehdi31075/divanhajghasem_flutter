# گزارش بررسی نسخه اولیه

## وضعیت جاری — ۲۰۲۶/۱۰/۰۶

- ویرایش متن با Flutter Quill 11.5.0 (نسخهٔ سازگار با SDK فعلی) انجام می‌شود. Delta و HTML پیش‌نویس به‌صورت اتمیک نگهداری می‌شوند؛ آزمون ویرایش قالب‌دار و بازگشایی SQLite، بازیابی دقیق Delta را تأیید کرد.
- تحلیل آخرین تغییر بدون مسئله و تمام ۵۳ آزمون پاس شدند؛ تبدیل متن فارسی، فهرست، پیوند و تصاویر نسبی، مهاجرت SQLite به نسخهٔ ۶ و ورود محلی debug هم پوشش داده شدند.
- صفحهٔ مطالعه تاریخ ایجاد و ویرایش را از `created_at`/`updated_at` نمایش می‌دهد. API زنده فعلی این فیلدها را ندارد و مقدار «ثبت نشده» نشان داده می‌شود؛ تاریخ ساختگی ایجاد نشده است.
- ورود موقت debug، مطابق درخواست کاربر، ابزارهای مدیریت را با بررسی محلی باز می‌کند؛ نشست واقعی PHP محسوب نمی‌شود و ارسال تغییر به سرور بدون آن متوقف می‌شود.
- رابط عمومی سه بخش خانه، دسته‌بندی‌ها و تنظیمات دارد. تب پیش‌نویس حذف شده و نوشته‌های ارسال‌نشده از تنظیمات ادمین در دسترس‌اند.
- باز کردن فهرست، کش موجود را فوراً نشان می‌دهد و سپس API را به‌روزرسانی می‌کند؛ شکست شبکه کش را پاک نمی‌کند.
- پنج لمس نسخهٔ برنامه، فرم ورود با حساب پنل را باز می‌کند. ابزارهای ایجاد، ویرایش و حذف پس از ورود موفق ظاهر می‌شوند و پس از خروج پنهان می‌شوند.
- `flutter analyze --no-pub`: بدون مسئله. `flutter test --no-pub`: همهٔ ۴۷ تست پاس شدند، از جمله مسیر ورود ادمین، خروج، دسترسی عمومی و کش آفلاین.
- نسخهٔ وب با تنظیمات `--wasm --web-browser-flag=--disable-web-security --no-pub --no-web-resources-cdn` روی پورت ۸۰۸۱ دوباره ساخته و اجرا شد. صفحهٔ عمومی با سه تب و بدون دکمهٔ نوشتن در پیش‌نمایش دیده شد.
- ورود با حساب واقعی و تغییر مطلب واقعی در این نوبت انجام نشده است؛ آزمون‌های CRUD با پاسخ‌های شبیه‌سازی‌شده اجرا شده‌اند.

## وضعیت جاری — ۲۰۲۶/۱۰/۰۵

- محیط: Flutter 3.41.9، Dart 3.11.5، macOS arm64.
- `flutter analyze --no-pub`: بدون مسئله.
- وضعیت این نوبت: فرم‌ها در Flutter و ذخیرهٔ مطالب روی سرور برقرار شد. `flutter test --no-pub` با ۴۳ تست پاس شد؛ دو تست تکمیلی ورود/انقضای نشست نیز جداگانه پاس شدند (جمعاً ۴۵ تست). تحلیل نهایی بدون مسئله است.
- تست فرم نوشتن تأیید می‌کند پاسخ دیرهنگام دسته‌های سرور عنوان و متن در حال ویرایش را تغییر نمی‌دهد و انتخاب دستهٔ سرور ذخیره می‌شود.
- تست تب جدید دسته‌بندی‌ها، استفاده از URL تصویر سرور، کارت‌های دو ستونه در عرض ۳۹۰، نگهداری جستجو بین تب‌ها، ارسال شناسهٔ دستهٔ انتخاب‌شده و باز شدن مطالبش را بررسی کرد. کارت‌ها در عرض ۳۲۰ با متن ۱.۸ برابر تک‌ستونه شدند و خطای چیدمان نداشتند.
- دسته‌های ثابت حذف شدند. تست‌های اختصاصی، نصب تازه بدون دستهٔ ساختگی، cache آفلاین، نام‌های تکراری سرور، فهرست خالی سرور، rollback دسته‌ها همراه cache و مهاجرت نسخهٔ ۲ به ۳ را بررسی کردند. یادداشت‌های عادی و حذف‌شده، نسخه‌های قبلی و outbox در مهاجرت حفظ شدند و foreign key فعال ماند.
- آزمون‌های `post_service_test.dart` و `post_widget_test.dart` قرارداد PHP، تأیید API، قطع ارتباط، نگهداری پیش‌نویس، ACK دیرهنگام، rollback کش، تعارض و فرم‌های داخل اپ را با سرور شبیه‌سازی‌شده پوشش می‌دهند. هیچ مطلب واقعی سایت در این نوبت ایجاد، ویرایش یا حذف نشده است.
- پیش‌نمایش با دستور `flutter run -d chrome --web-port 8081 --wasm --web-browser-flag=--disable-web-security --no-pub --no-web-resources-cdn` دوباره ساخته و اجرا شد؛ ساخت وب موفق و پاسخ `http://localhost:8081/` برابر HTTP 200 بود. اتصال محتوا مستقیم به API سایت است؛ سرور API یا proxy محلی راه‌اندازی نشد.
- `dart run tool/check_legacy_api.dart`: اتصال واقعی HTTP؛ ۳۲ دسته، ۱۲ مطلب در دستهٔ ۶۱ و مطابقت عنوان فرعی/HTML جزئیات مطلب ۱۱۷ با فهرست تأیید شد. سایت تغییر نکرد.
- Android تولید شد و INTERNET و مجوز HTTP دامنهٔ فعلی در manifest/config قرار گرفت. ساخت APK در `mergeDebugJavaResource` با `No space left on device` شکست خورد. خروجی‌های موقت همان ساخت پاک شدند. APK قابل تحویل تولید نشد.
- بنا به درخواست کاربر، اجرا روی وب ادامه یافت؛ گوشی وصل نشده و آزمون واقعی Android انجام نشده است.
- `flutter build web --wasm --no-pub --no-web-resources-cdn` موفق بود. سپس پیش‌نمایش با دستور Chrome بالا دوباره اجرا و آخرین سورس ساخته شد. خانه و فرم «مطلب تازه» با دکمهٔ «ذخیره روی سرور» در مرورگر بازبینی شدند. نشست نوشتن روی سایت واقعی و CRUD واقعی در این نوبت اجرا نشده‌اند؛ تست آن‌ها با پاسخ شبیه‌سازی‌شده است. در مرورگر داخلی Codex بارگذاری دسته‌ها خطا داد؛ علت دقیق آن در این نوبت تأیید نشده است. محدودیت CORS و کوکی مرورگر همچنان به تنظیم سرور بستگی دارد. بازبینی پنجرهٔ Chrome کامل نشد: بازبینی خودکار فهرست برنامه‌ها/پنجره‌ها را به دلیل احتمال افشای متادیتای خصوصی نامرتبط رد کرد و دسترسی محدود به زبانهٔ مشخص localhost نیز به علت در دسترس نبودن مرورگر Chrome در ابزار برقرار نشد.
- SQLite مرورگر با WASM و worker محلی راه‌اندازی شده است. دادهٔ وب مستقل از دادهٔ گوشی و وابسته به origin مرورگر است. این مسیر برای پیش‌نمایش است؛ پشتیبان خارجی ایجاد نمی‌کند.

مطالب زیر گزارش تاریخی بستهٔ اولیه‌اند؛ عبارت‌های «اجرا نشده» در آن‌ها وضعیت زمان تهیهٔ بسته را بیان می‌کنند.

## بررسی‌های انجام‌شده

- ۱۶ فایل Dart با parser مستقل Tree-sitter از نظر دستور زبان بررسی شد؛ خطای نحوی گزارش نشد.
- مسیر importهای محلی به فایل‌های موجود می‌رسند.
- هر سه فایل قلم TTF معتبرند و نویسه‌های فارسی دارند؛ مجوز OFL کنارشان قرار دارد.
- هشت دستور واقعی schema/pragma/index استخراج‌شده از سورس با SQLite اجرا شد.
- بازگشت تراکنش SQLite هنگام شکست درج outbox بررسی شد؛ متن قبلی حفظ شد.
- حذف outbox با شرط revision بررسی شد؛ تأیید نسخه قدیمی رکورد تازه‌تر را حذف نکرد.
- دستور واقعی محدود کردن history به ۲۰ نسخه اجرا و نتیجه بررسی شد.
- امضاهای CardThemeData، DropdownButtonFormField.initialValue و ListTile.minTileHeight با سورس Flutter و exportهای sqflite با سورس بسته بررسی شدند.

این بررسی‌ها جای اجرای Dart یا آزمون‌های Flutter را نمی‌گیرند. parser تنها دستور زبان را بررسی می‌کند و تحلیل نوع، build، اجرای UI یا رفتار سرویس SQLite از داخل Dart را تأیید نمی‌کند. بررسی‌های مستقل SQLite تراکنش و SQL را پوشش می‌دهند، نه اجرای repository در Dart.

## آزمون‌های نوشته‌شده اما اجرا‌نشده

`test/persistence_test.dart`:

- بازگشایی پایگاه داده و بازیابی متن و موقعیت مطالعه بدون سرور
- rollback یادداشت و نسخه قبلی اگر درج outbox شکست بخورد
- ترتیب ذخیره ۳۰ ویرایش سریع و مقاومت در برابر ACK قدیمی
- حفظ متن در حذف و بازیابی
- نگهداری یک نسخه کامل قبل از هر نوبت ویرایش، به‌جای نسخه‌های بی‌فایده تک‌حرفی

`test/mobile_layout_test.dart`: راست‌به‌چپ بودن خانه، باز شدن ویرایش و بررسی خطاهای چیدمان در عرض ۳۲۰ و بزرگ‌نمایی متن سیستم ۱.۸.

## محدودیت محیط اولیه

هنگام آماده‌سازی Flutter SDK، بازبینی خودکار اجرای بررسی نسخه Flutter را رد کرد؛ دلیل اعلام‌شده دسترسی ناخواسته ابزار به endpoint متادیتای محیط بود. این رد دور زده نشد. در نتیجه Flutter analyze، Flutter test، تولید پروژه بومی Android، بررسی تصویری UI اجراشده و ساخت APK انجام نشد.

پلاگین Figma نیز به سقف درخواست رسیده بود. دریافت high-fidelity design context ممکن نشد؛ انطباق پیکسلی کد با Figma تأیید نشده است. کد از مشخصات محصول و سبک تصویری طراحی‌شده ساخته شده است.

## پذیرش پیش از استفاده واقعی

روی گوشی مقصد، حالت هواپیما را روشن کنید؛ یک یادداشت تازه بنویسید، پایان ویرایش را بزنید و برنامه را ببندید و دوباره باز کنید. عنوان و متن باید عیناً باقی باشند. متن بلند را باز کنید، کمی پایین بروید، از صفحه خارج و دوباره وارد شوید؛ آخرین موقعیت باید بازیابی شود. همان متن با قطع اینترنت باز بماند.

خطای ذخیره را به‌صورت کنترل‌شده در نسخه آزمایشی شبیه‌سازی کنید؛ نشان «ذخیره شد» نباید نمایش داده شود و خروج از ویرایش تا تلاش مجدد موفق بسته بماند. پیش از انتشار، خروجی و بازیابی پشتیبان واقعی و مهاجرت نسخه‌های schema باید اضافه و آزموده شوند.
